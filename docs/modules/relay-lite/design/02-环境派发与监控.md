# 环境派发与通用 watcher · 产品设计与验收

# RLT_35 · 按环境配置派发（已确认）

用户原话（初始需求及补充均纳入本卡）：
“skill 里面可以加上 herdr skill 我感觉 codex 不太会在herdr里面派发任务。其次，codex 也不太会用 watcher监控各个agent状态”

初始需求：
“不同的环境任务派发方式不同。比如：herdr、orca 之类的。最好是按配置来，每一种都有自己的派发方式。目前有且只有herdr，派发方式就是 开space->开标签页->开交互式agent。如果有新任务/新批次，同标签页模型 clear 再派发”

## 目标与消费路径

把现有协议中的 Herdr 派发细节集中到环境协议，由环境配置选择；模型 adapter 保留模型差异与指向环境协议的入口。目前仅注册 herdr。配置由小型可执行校验工具 tools/environment_config.py 实际读取；工具只返回选中环境和协议路径，不启动 agent、不自动派发。交互式 agent 根据校验结果读取环境协议执行。

拟新增 skill/environments.toml：默认环境 herdr；每种已实现环境登记其独立派发协议路径。本卡只登记 herdr -> references/environment-herdr.md。核心及两 adapter 入口先执行安装包内 environment_config.py -> 工具读 environments.toml，选定环境并校验 schema、注册项、协议文件与实际运行环境 -> 输出选中环境及协议路径 -> 登记 execution_strategy.md 的 environment 字段 -> 按该环境协议派发。首次建卡使用用户/派单明确的 environment；未指定时使用配置 default=herdr。恢复只使用 execution_strategy.md 已登记的 environment，若新指令不一致先停止处理，不偷偷切换。工具接受显式选择参数，但恢复时必须传入已登记值；roles.toml 不参与环境选择。只有选择参数缺省才能使用配置内 default；配置文件或 default 缺失、重复/非法字段、默认项未注册、环境不满足、协议缺失、相对路径越界、选中未知环境均非零退出阻止派发，不猜测、不回退。工具输出采用固定可测试结构及固定原因码，不输出环境变量或凭据。新环境通过新增专属协议并注册配置接入，不复制到两份模型 adapter。

Herdr 专属协议进入时先读取当前安装版 `herdr --skill`，不是只在文档中提及名称；本机三个技能目录没有独立 herdr/SKILL.md，CLI 内置 skill 已核实可读取。先检查 HERDR_ENV=1，再执行任何控制命令，不伪造变量；命令语法以当前 CLI help 为准，agent 名/ID 从 JSON 读取。Herdr skill 的默认同 tab 分 pane 与本用户指定拓扑不一致时，按用户与 relay-lite 卡合同采用 space -> 独立 tab -> 交互式 agent，并明确此优先级。无需复制上游整份 skill，入口直接获取当前版本，离线 CLI 缺失则停止。

Herdr 专属协议统一承载创建 space、创建独立具名 tab、启动交互式 agent、原生 clear 与确认、派单及投递确认、观察/通信入口；模型 ID/推理档及模型原生命令仍按用户确认和对应模型能力；各模型 adapter 规定从当前模型帮助/实际 UI 核实原生清理命令及新空会话可见判据，不以 state_change_seq 推进冒充 clear 成功。Herdr 内置 skill 读取失败/无法识别即停止，记录 CLI 版本和来源，不保存全文或凭据。首次派发严格 space -> tab -> 交互式 agent -> 派单，不使用 headless 代替。

新任务/新批次复用同 tab 时，保存前序工件及 signal，核前置完成条件，单独清理模型会话并确认成功，再投递新派单；不是 shell clear，不合并 clear 与派单。新批次沿用前批 durable PASS 和工件齐全条件。FAIL/整改及 E2 targeted attempt 2 留原会话和计数；fresh reviewer 使用独立新实例，watcher 保持常驻；历史 signal/证据与 RELAY_* 保留。clear 失败或未知即停止新派单。

环境配置与 roles.toml（模型默认提案）分开；execution_strategy.md 保存选中环境、配置/协议来源以及实际 space/tab/pane/agent 身份用于恢复。恢复核实际环境及已有选择，不擅自切换。跨卡创建、通知/交接和 watcher 的 Herdr 能力也指向环境协议，避免核心宣称通用却仍从模型 adapter 写死 Herdr。

watcher 为所有 agent 提供独立可照做的通用操作路径及派单样例（持久 exec cell/session_id/write_stdin 属于 adapter-codex.md 的宿主说明，Herdr 专属协议只放 CLI/监控合同；Claude adapter 保留其宿主对应写法）：核模型确认、真实 space/notify/self 与 RECEIPT/环境 -> 创建独立 watcher tab 并启动交互式 watcher -> watcher 用持久 exec session 运行固定 space_watch.py -> 编排核 watcher 与脚本实际启动证据后再依赖其监控。每 120 秒脚本动态发现该 space 其它 agent，排除自身/编排，读取 agent_status/state_change_seq，变化才通知；watcher 巡检精确子进程存活/退出。不把外层函数 Script running 当真实子进程存活；拿到运行 exec cell 才 wait，取得 exec session_id 才 write_stdin。进程退出或通知未知时一次报阻塞、保留现场、不自动重发重启。编排收到提示后读 durable signal 和独立报告再路由，不以 idle/done 认完成。watcher 缺席采用有接收者的有界等待，不结束回合后无人接收空等；repo/workspace 零写入。现有脚本语义不变，新增能让所有零上下文 agent 照做的启动/确认/巡检步骤与常见误用反例。

## 单卡范围与计划

建议标准档，任务类型 normal：无生产操作、不可逆迁移、数据口径或权限/共享保证变更；有协议行为和配置路由变更。一张卡 RLT_35，wt/RLT_35 -> master；确认后建该卡 worktree。

实施范围：skill/SKILL.md、两模型 adapter、新 environments.toml、新 environment-herdr.md、新 tools/environment_config.py、安装工具文件清单与相应 tests（test_environment_config.py、test_install_skill.py、test_contract.py）、README、按需模板中环境来源登记、正式设计输入和 DevPlan/workspace/as-built 工件。archive 与其它卡工件只读。tools/space_watch.py 维持现有 Herdr 实现，本卡不实现 Orca，不安装到真实用户 skill 目录、不操作现有 agent/tab、不部署/重启。

阶段：正式设计和卡落户/隔离 -> 环境配置及协议路由/安装分发 -> 配置、生命周期反例和隔离安装回归/有效单测 -> fresh 独立 code_review -> 必要 Ubuntu/Windows CI 和 PR -> 服务端合入、合入态复验、verify(relay-lite) 及本卡收口。开工授权覆盖本卡全程交付，不覆盖下一卡或环境操作。

## 机器验收

- RL35-M1：安装包配置目前有且只有 herdr；默认与显式选择一致；未知环境、配置错误或协议缺失阻止派发，不能回退。
- RL35-M2：核心及两模型 adapter 先读取环境配置再走专属协议；Herdr 派发/通信入口只在其专属协议维护；原有调用点无遗漏。
- RL35-M3：Herdr 首次按 space -> tab -> 交互式 agent -> 派单；复用同 tab 的新任务/新批次先模型原生 clear、核成功，再派单；失败/未知阻止派单。
- RL35-M4：RLT_34 完成条件、整改/E2/fresh/watcher 例外以及历史证据、计数和 RELAY_* 保留；配置选择不扩大模型、角色或开工授权。
- RL35-M5：三端隔离安装包含配置、校验工具和环境协议，并纳入 manifest 哈希；安装缺件失败，安装后引用可独立解析，不依赖此仓 checkout。
- RL35-M6：Herdr 派发前明确加载当前 herdr --skill；有环境/实际 ID/当前 CLI 语法核对及用户拓扑优先级，缺失时停止。
- RL35-M7：所有 agent 的 watcher 入口覆盖启动、真实子进程确认、120 秒动态监控、通知确认/退出处置与 durable signal 路由；复用现有脚本测试对新增/离开/状态变化/排除项/未知通知/无写入的证明，协议样例无工具调用层级混淆。
- RL35-M8：适用回归、有效单测 RED -> 恢复 GREEN、fresh 独立代码复核、必要 CI、合入态复验及 verify 齐备。

验收证据为配置读取/路由检查、协议契约回归、隔离安装与错误用例、独立复核和 CI，不宣称执行了真实 Herdr 新开 space/交互式模型演练。若需真人使用判断或实时环境演练，先明确相应操作范围，再执行；本卡没有额外主观人判结果项。
