### 候选-001 · 拆分产品前先枚举仓外测试入口

触发场景：产品目录迁出到独立仓时，源仓仍需保留 Runner 回归与退役边界。 · 建议分类：行为流程 · 来源：RLT_33 findings F6、workspace lesson L1
疑似重复：无
- 现象：只按产品目录退役后，源仓专属 PowerShell suite 仍调用已迁出的 relay-light 产品路径，导致完整回归末尾失败。
- 反思：迁移闭集只枚举产品文件，未同时从测试入口反查其被调用的产品路径。
- 建议后续动作：拆分前先从所有测试/CI/suite 入口建立“入口 → 被测产品路径”清单；退役时逐项决定迁移、改为退役断言或保留，并在源仓全套回归验证。
状态：待裁决

### 候选-002 · 变更性取证在冻结副本运行

触发场景：迁移/删除会改变被测文件，且需要保留基线、变异或回归取证。 · 建议分类：行为流程 · 来源：RLT_33 findings F5、workspace lesson L2
疑似重复：无
- 现象：旧全量基线在活动工作树删除源文件的同时仍在运行，结果失去可归因性。
- 反思：取证过程和待变更工作树共享同一文件集，运行期间的输入不再固定。
- 建议后续动作：在开始长测试前用精确 SHA 建立独立 Git 副本；记录副本 SHA、命令和输出。活动树发生变更后，已受影响的运行只能保留为无效历史，不能作为放行或 RED 依据。
状态：待裁决

### 候选-003 · 祖先提交审计须在 CI 明示完整历史前提

触发场景：仓库契约测试用固定祖先提交验证一次性迁入内容。 · 建议分类：编码陷阱 · 来源：RLT_33 review.code2 最终补充、findings F11、`evidence/shallow-ci-failure.log`
疑似重复：无
- 现象：固定 `import_commit=9458e4f` 的审计在 GitHub Actions 默认 shallow checkout 中缺少祖先对象，Windows/Ubuntu matrix 均失败；本地完整 Git 的 39 项测试通过。
- 反思：测试把完整 Git 历史当作隐含运行前提，却没有把该前提写进 CI checkout 配置，导致有效审计无法在干净 CI 环境取证。
- 建议后续动作：凡测试会读取或验证祖先提交，先在 CI 显式声明并验证所需 history depth（本卡为 `fetch-depth: 0`）；保留浅 clone 的失败归因，并确认修复未 skip 审计、未降级为只核当前文件。
状态：待裁决
