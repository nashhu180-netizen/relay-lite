# RLT_35 环境派发方案独立审核（侦测型降级；非机器只读）

本审核未执行测试、未连接或控制 Herdr 实态，也未核验实际 `HERDR_ENV`；以下仅根据提案、当前仓库文本和代码作静态核对。用户原话为：“不同的环境任务派发方式不同。比如：herdr、orca 之类的。最好是按配置来，每一种都有自己的派发方式。”

## 方案问题

- **P0｜环境配置尚未冻结为“实际消费”的接口。** 提案说“入口读取配置 -> 选定环境”，但未规定消费方（哪一份 core/adapter/工具代码）、解析方式、显式选择字段/优先级、schema、合法值和配置来源。当前仓库的运行入口是三份 Markdown 协议；`tools/install_skill.py` 的 `SKILL_FILES` 仅打包 `SKILL.md`、两个 adapter、`roles.toml`、`space_watch.py` 和模板，当前不存在 `environments.toml` 或环境路由器。若只新增文本和文本断言，配置仍可能只是说明，不能证明任何派发路径真的依据它选择。应在开工前把“由协议 agent 消费的声明式路由”与“由可执行路由器消费”二选一，并对所选机制写出可测的输入、选择、失败出口和禁止 fallback 合同。

- **P1｜配置的失效/默认语义内部尚有歧义。** “缺失可使用显式默认 herdr”与“配置损坏、选中未知环境或协议缺失均停止”合理，但没有定义“显式选择”的载体，也没有说明配置缺少 `default`、默认项未注册、相对协议路径越界、同名重复或安装后路径重定位时的结果。M1/M2 应逐项覆盖这些负例，并确认 `roles.toml` 只保留模型提案、不能成为环境选择的暗门。

- **P1｜Herdr 内置 skill 的边界正确，但证据契约还不够具体。** 当前仓库把 Herdr 命令写在两个 adapter；提案改为每次进入 Herdr 协议先读取当前 `herdr --skill`，且不复制上游全文，这与“当前 CLI 为准”相符。应补：读取失败/输出无法识别时的精确 BLOCKED 结果、记录的版本/来源摘要（不落凭据、不存全文）以及当内置 skill 默认 sibling-pane 与用户要求的 `space -> 独立 tab -> 交互式 agent` 冲突时，以用户/卡合同优先的可检验步骤。静态测试只能证明协议文字；本卡不做实态创建，不能宣称当前 CLI 真能完成这些命令。

- **P1｜原生 clear 的“确认成功”没有可复核判据。** 现有两 adapter 已要求“已核实支持的原生会话清理命令”、清理与派单分离，且明确 shell `clear` 不可替代；当前合约测试还检查 `/clear`、不能清 `RELAY_*`、整改/E2/fresh/watcher 例外。提案应为每种模型 adapter 指定：如何取得该模型当前原生命令、何种可见结果构成成功、结果未知时保留何种记录及停止点；不得仅以 `state_change_seq` 推进当作 clear 成功。

- **P1｜watcher 路线应复用既有脚本合同，不能把宿主工具层级写成 Herdr 能力。** 仓库的 `space_watch.py` 已在脚本内存中每 120 秒动态发现同 workspace agent，排除 self 与 notify pane；通知使用 `herdr agent prompt --wait --until working --timeout 5000`，并要求 pane 一致、`working` 和 sequence 推进，否则 fail-closed。提案正确指出持久子进程、`exec` cell / `session_id` / `write_stdin` 的不同层级，但应把它限定为 Codex 宿主操作说明，不写入通用 Herdr 环境协议；同时写明无法取得持久 session、子进程退出、通知未知各自只一次报阻塞并保留现场，编排仍只读 durable signal 与独立报告路由。现有 watcher 是观察/报信，不是完成、授权或自动重启来源。

- **P1｜安装独立可用性的验收缺少精确变更面。** 当前安装器的封闭清单和现有测试均断言三端安装后文件集合严格等于 `SKILL_FILES + manifest.json`，并以哈希验证。因此 RLT_35 必须同时更新 `SKILL_FILES`、来源缺件 fail-closed、manifest 哈希和隔离安装测试，检查新配置与 `environment-herdr.md` 的相对引用在 `.claude/.codex/.agents` 三个已安装目录均可解析，且不依赖 checkout。提案的 M5方向正确，但“安装工具文件清单”应列为允许路径和可交付物，防止只改文档导致安装包漏件。

- **P1｜机器证据边界应写得更醒目。** 本卡可以证明配置/协议文件、安装包、静态路由与 watcher 单测契约；不能证明真实 Herdr 的 space/tab/交互 agent/clear 或通知在某个实时 session 成功。提案末段已有此界限，建议把同一限制写进验收结果模板，避免把离线 GREEN 误读为 Herdr 实态演练完成。

## 用户理解风险

- “按配置派发”容易被理解为仓库会自动读取并执行 Herdr/未来 Orca。提案同时写“agent 读取的派发路由契约”“不新增自动派发引擎”；若继续采用此含义，配置只能约束被派发的 agent 行为，不能强制拦截偏离路径。用户确认时应明确这是协议级消费还是要新增可执行路由层。

- “skill 里面可以加上 herdr skill”若被理解为把 Herdr skill 打包进 relay-lite，会与提案的“运行时读取当前 `herdr --skill`、不复制上游”不同。后者避免陈旧副本，但离线/CLI 缺失会停止，安装包也不能自足地提供 Herdr 功能；应把此依赖和停止行为明示为用户接受的范围。

- watcher 能唤醒编排并报告状态变化，却不能替代 durable signal、独立审查或人验。真实子进程存活、投递确认与“任务已完成”是三件不同的事；现有代码也明确在通知未知时不提交新基线。若用户期待 watcher 自动接续/自动重试，需要另行定义并授权，不能从本卡推得。

- 仅 Herdr 注册符合“目前有且只有herdr”，但未来 Orca 接入不是本卡验收项。若验收语言写成“每一种都有自己的派发方式”而没有补“已注册环境”，会造成已实现多环境的错误印象。

## 需要用户决定的问题

1. **P0：环境配置的消费层级。** 请确认本卡的“按配置”是 A) 协议 agent 在进入时按 TOML 契约人工/模型解析并 fail-closed，还是 B) 新增可执行的路由/校验工具并以该工具的结果作为派发前提。两者的可靠性、测试形式和允许路径不同；提案目前同时使用“读取”和“不新增自动派发引擎”，不足以唯一确定。
2. **P1：选择来源与优先级。** 显式环境选择由任务 `execution_strategy.md`、派单字段、用户启动参数或其它固定来源给出？当其缺失时才取配置默认 herdr，还是必须每卡明示？此决定影响恢复是否可复现，也决定“默认”是否会掩盖意外环境。
3. **P1：实态验证是否另开授权。** 当前卡的离线验收不能证明 Herdr 实态；若需要验证 `herdr --skill`、space/tab/交互 agent、原生 clear 或 watcher 持久进程的真实运行，请单独确定目标环境、允许的创建/清理范围及成功证据。本审核不建议把该操作隐含进标准档施工。

## 定向复审结论（修订稿）

修订已实质闭合原 **P0**：`tools/environment_config.py` 被定义为实际读取 `environments.toml`、校验并固定结构/原因码输出的可执行前置；它只选择环境和协议路径，交互式 agent 才按结果执行，因而没有扩成自动派发引擎。首次的“用户/派单显式值 -> 配置 default”以及恢复只采 `execution_strategy.md.environment`、不一致即停止，也消除了默认值掩盖恢复时静默切换的歧义。`roles.toml` 被明确排除出选择路径。

原 **P1** 亦获得可施工的边界：配置 schema、重复/非法字段、缺 default/未注册项、未知环境、路径越界和缺协议均非零阻止；原生 clear 改为按各模型当前帮助/实际 UI 的新空会话判据确认，不以 sequence 代替；`herdr --skill` 读取失败/不可识别停止且只记录版本/来源；Codex 的持久 exec/session_id/write_stdin 仅留在 adapter-codex，Herdr 环境协议保持 CLI/监控合同；安装闭包明确包含配置、校验工具和环境协议，且 M5 要求三端隔离安装和 manifest 哈希；离线测试不再被表述为实态 Herdr 演练。

仍建议施工时把 `environment_config.py` 的 CLI 输入、固定 JSON（或等价固定）输出字段和每个 reason code 一一写进 `test_environment_config.py`，并让两个 adapter 的文本契约测试断言“先运行已安装副本的工具、非零即停止”。这是实现级 P1 收口项，不再是需要用户决定的 P0。此次复审仍为侦测型降级、非机器只读：未运行测试、未控制 Herdr、未核验实时环境或实际安装结果。
