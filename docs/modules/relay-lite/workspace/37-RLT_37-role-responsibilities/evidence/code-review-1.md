## 独立判断

核心角色表和 single-task 边界把编排限定为组织已授权工作、核状态/证据来源、识别偏离、路由和跟踪决定；测试、取证、归因、验收判断仍交给 executor/reviewer。`decider` 的决定权限闭集明确保留，咨询不授予取证、资源操作、派活、验收或扩权，因此没有把“完整解决路径”改造成编排或顾问的新增执行权限。

决策指南要求从当前状态到验收的步骤、依赖、失败分支、权限/预算、验证与收束，并明确 DECIDED 不是 PASS 或资源操作授权。两个 adapter 都把目标/当前位置、授权/停止线、后续去向和 decision 专用完整路径写入派单模板；安装器把指南纳入封闭包，安装测试在真实安装目标中校验每个入口都能链接、manifest 有同一字节哈希，且缺指南会在任何安装前 fail closed。该覆盖是有意义的分发回归，不只是对 `SKILL_FILES` 自身的字符串断言。

对协议做独立静态推演的结论如下：

- S1：已有完整授权且结果符合预期时，直接按既定路径推进，不增 decider 或用户审批闸。
- S2：窄构建授权已经成功并要求停止时，原停止线仍有效；只能准备复现、修复、RED→GREEN/复测/复核/收束的完整建议和预算/审批点，集中请用户裁决，不能把构建许可解释成测试或修复许可。
- S3：同类失败或额度不足保留失败/计数，受影响动作停止，带历史交 decider 比较替代路线；不得重置额度、换实例后重试或申请另一个碎片包。
- S4：实例身份或结果未知时停受影响动作并保留证据；紧急安全或生产风险命中停止条件时立即停止新动作并报告，均不等顾问分析，也不借紧急扩权。
- S5：路线 A 待用户裁决只暂停其依赖动作；无依赖且已授权的路线 B 继续。
- S6：decider 对未获准的路线只能研究现有证据和提出推荐；不能试跑、派活、代验收或把咨询当执行许可。

这些结论来自协议文本和测试的离线静态核对；没有把它们表述为真实业务会话、线上审批次数下降或环境行为已被证明。
