# RLT_39 协议场景验证准备

本表检查文字合同能否唯一给出符合原权限的行动；不是运行真实模型的行为实验。主会话已逐项对照候选条款：12个场景在orchestration的四项规则、下方角色/决定权限及watcher有界等待中均有明确去向；独立复核尚待执行。所有场景保留原卡授权、预算、模型确认和signal要求。

| 场景 | 应有下一步与责任 | 禁止推断 |
|---|---|---|
| 已汇报实现成功，测试/复核仍未做且均已授权 | 编排派原责任方完成后续，核证据接续 | 已汇报=已完成；等用户再说继续 |
| 用户问进度/为何阻塞 | 简洁回答后核未完成项并继续可执行步骤 | 插问=暂停原任务 |
| 用户问“是否有这个问题”，本卡已授权排查修复 | 路由核实，有问题则组织修复、验证与复核 | 回答“有”就停；编排代跑测试 |
| 同一句问题指向范围外模块 | 记录发现和待决，继续原任务 | 默认开新卡/扩路径 |
| worker BLOCKED仅为报告缺证，原补证许可仍有效 | worker停止，编排按原会话/轮次路由补证 | worker自派活；编排代写结论 |
| 反复同类阻塞或单步成功仍无验收路径 | 编排提供证据/历史/剩余权限，decider重审完整路径 | 同类单步包循环、换会话清零预算 |
| 需要用户权限，另一项无依赖且已授权 | 具体方案问用户，继续另一项 | 因一个待决冻结全卡；默认授权 |
| 运行结果/身份未知或预算耗尽 | 停受影响动作，保现场，给解除条件/责任方/恢复第一步 | 自动重试、杀进程、追加预算 |
| 用户明确暂停或原停止线命中 | 按原范围停止，仅执行已授权处置 | 为主动推进忽略停止要求 |
| worker正常运行，PENDING | 有接收者的有界等待与按合同核状态 | 单次超时=失败；final后无人接收 |
| decider未获模型确认/不可用 | 遵守分配闸并明确缺口，继续独立许可内工作 | 擅自换模型；编排代作技术决策 |
| 所有适用条件/独立原证据满足 | 报告本卡授权范围内完成 | 单个DONE、DECIDED或通知=整卡PASS |

检查结果：M1对应场景1–4、10、12；M2对应5–8、11；M3对应4–12。候选条款未改变worker/decider写者或计数；测试80项通过只证明既有包/工具回归，不证明模型执行这些规则的概率。
