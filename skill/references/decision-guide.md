# decider：完整解决路径与任务调整

本指南由核心 SKILL「编排职责与执行边界」引用；权限、模型分配、写者、signal、复核与停止线仍以核心和当前卡合同为准。decider 对建议能否推进原目标负责，不承诺未经执行的结果，也不代替执行者或 reviewer 产证。普通步骤已有路径和授权时直接执行，不调用 decider 逐项审批。

## 交给 decider 的输入

编排提供原目标与验收、当前结果及原证据、已授权范围/资源/预算与已耗额度、明确停止线、需要判断的变化、历史同类阻塞和已尝试路线。引用现有 brief/findings/报告即可，不重抄账本。缺失的执行事实交原产出方补证；编排与 decider 均不凭摘要猜归因。

## 一份决定应回答什么

沿用 `decision.<d>.md`，小问题可用一段话覆盖，不强制另建模板或填不相关长表。

1. **目标与问题**：当前路线是否仍能达到原目标？问题是实现、方法、依赖还是授权边界？判断依据和缺失事实是什么，由谁补证？
2. **完整路径**：从当前状态到验收还需哪些步骤、依赖、验证与资源收束？主要失败分支如何处理？成功走到哪里，剩什么？不能只写下一条命令。
3. **选择与权限**：推荐路线及理由、必要的替代路线与代价；逐项区分已有权限内决定与用户待决事项，引用原授权和剩余额度。允许修复的类型/范围及次数沿现有合同，缺许可时提出具体建议，不自造数字或授权。
4. **有效性与停止**：执行者应提供什么结果、reviewer 按什么标准核验？结果不符时怎样在许可内修复/换路，什么情况必须停？保留失败历史，身份或结果未知不自动重试。
5. **后续用户决定**：本轮成功后是否仍有可预见的审批点？哪些可本次一起提交，哪些必须等新事实及其原因？确实没有写“无”并说明覆盖依据；不能保证时如实说明。再次询问交代新增事实或此前规划遗漏及补救，不能无限重复同类限定包。

咨询可以研究用户尚未批准的路线，但不允许试跑、派活、扩路径、使用外部资源或改变验收。触及用户权限时仍应给出准备充分的建议，而非只写“请用户决定”。完整路径不要求冻结全部实现代码；执行细节留给获授权 executor，避免将脚本字节变化误作新增授权。原合同明确冻结版本/字节或单次额度的仍必须遵守，变更先按原合同处理。

## 编排消费决定

核 decision 对象/版本、证据来源、上述必要内容、权限与预算引用是否齐备。缺项退原 decider；归因缺证回 executor/reviewer，不由编排重算。用户待决部分不得直接执行；可独立推进的授权内工作继续。记录和通知走 findings，执行策略只放指针。

执行和复核完成后，核结果与决定约定的目标/去向是否一致。正常结果按已定路径继续；重复同类阻塞或局部成功仍无完成路径，带历史回 decider 重审路线。DECIDED 不是 PASS，更不是资源操作授权；不清零失败、整改计数，不替代独立复核。

紧急停止、安全或生产影响先按现有停止规则处理并立即报告，不等研究或集中询问；处置本身仍限已授权动作。decider 不可用时遵守原分配/停止规则，由主会话报告实际阻塞并集中补齐缺失授权，不私自换模型，也不阻断无关已授权工作。

## 正反例

| 场景 | 应有处理 | 错误处理 |
|---|---|---|
| 原方案覆盖实现、测试、复核，当前结果符合预期 | 编排核原证据与适用复核，按授权推进下一步 | 每一步先问 decider，再请用户确认 |
| 允许路径内两种兼容修法，原测试额度足够 | decider 比较后决定；说明修复→复测→复核→收束路径及失败去向，编排知会后派发 | 将普通技术选型逐项交用户 |
| 用户上一轮只批配置修正与一次构建，构建已成功并要求停 | 遵守原停止线；decider 提出复现→修复→复测→收束的具体后续方案，列明资源、预算建议和审批点，编排集中请用户裁决 | 将此前构建许可解释为测试许可，或只申请一次测试却隐去必然还需修复/复测的申请 |
| 测试拿到有效 RED，但目标是修好产品 | 依据已有修复/复测许可继续，缺许可则提完整剩余方案；不能把 RED 当完成或自然终点 | 不分析剩余路径，每成功一步再造一份停止包 |
| 两次同类准备失败，均有明确失败证据 | 保存原计数与结果，decider 检查方法是否合适并比较替代路线；剩余权限/额度不足交用户 | 改目录、换实例、重置计数，再申同类单步包 |
| 授权内脚本参数写错，允许该类修复且额度足够 | executor 修复并按合同验证；需要改变路线才转 decider | 把普通纠错一律升级为新增授权 |
| 必须新增外部数据库或改变验收标准 | decider 基于已有证据给备选/推荐、成本和影响，编排集中问用户；不试连或以本地模拟替代原验收 | 顾问以“目标需要”为由自动批准资源或放宽标准 |
| 进程/实例身份未知、动作结果未知或预算耗尽 | 受影响动作停，保留证据和现场，按原规则报告并提出后续建议；不自动重试/清理 | 先补跑或杀进程，再补授权和记录 |
| 紧急风险已触发停止条件 | 立即停止新动作并报告，仅执行原已授权安全处置 | 等 decider 写完方案或凑齐其他问题才报告 |
| 路线 A 需要用户决定，路线 B 的工作独立且已获准 | 编排暂停 A 的依赖动作，同时继续 B | 有一个 D 项便冻结整张卡所有工作 |

这些是协议推演样例，不是实际业务运行记录，也不证明真实会话的审批次数已经下降。
